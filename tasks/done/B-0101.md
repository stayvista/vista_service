# B-0101 — Catalog Service: 숙소/룸타입 CRUD API



## Goal
숙소(프로퍼티)와 룸타입을 관리/조회할 수 있는 API를 만든다.
    Search/Booking/Ticket/Package가 모두 Catalog를 기준으로 동작한다.



## Scope
- Admin CRUD:
      - `POST /v1/admin/properties`
      - `PATCH /v1/admin/properties/{propertyId}`
      - `POST /v1/admin/properties/{propertyId}/room-types`
      - `PATCH /v1/admin/room-types/{roomTypeId}`
    - User read:
      - `GET /v1/properties/{propertyId}`
      - `GET /v1/properties` (pagination)
      - `GET /v1/properties/{propertyId}/room-types`
    - 상태/노출:
      - status=ACTIVE만 user에 노출
    - Outbox 이벤트:
      - `PropertyUpserted`, `RoomTypeUpserted` (Search 인덱싱용)



## Non-goals
- 가격/프로모션 엔진은 v2 (v1은 room_type.base_price 정도만)
    - 이미지 업로드는 v1에서는 URL만 받음(S3 연동은 v2)



## API Contract (Admin)
### POST /v1/admin/properties
- `X-Request-Id` (optional): 클라이언트가 생성한 요청 ID (없으면 서버 생성)
- `Idempotency-Key` (쓰기 API 필수): UUID 권장. 동일 요청 재시도 시 동일 결과 반환
- `Authorization` (optional in MVP): `Bearer <token>` (MVP에서는 `X-User-Id`로 대체 가능)
- `X-User-Id` (MVP only): 숫자 사용자 ID (인증 도입 전까지 임시)
Request:
```json
{
  "partner_id": 300,
  "name": "Wanderly Hotel Seoul",
  "country": "KR",
  "city": "Seoul",
  "address1": "123 Teheran-ro",
  "lat": 37.501,
  "lng": 127.0396,
  "status": "ACTIVE"
}
```
201 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "property_id": 1001
  }
}
```

### POST /v1/admin/properties/{propertyId}/room-types
Request:
```json
{
  "name": "Standard Double",
  "max_guests": 2,
  "base_price": {
    "currency": "KRW",
    "amount": 120000
  },
  "status": "ACTIVE"
}
```
201 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "room_type_id": 2001
  }
}
```



## API Contract (User)
### GET /v1/properties/{propertyId}
200 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "property_id": 1001,
    "name": "Wanderly Hotel Seoul",
    "city": "Seoul",
    "lat": 37.501,
    "lng": 127.0396,
    "amenities": [
      "wifi",
      "parking"
    ],
    "status": "ACTIVE"
  }
}
```

### GET /v1/properties?city=Seoul&cursor=...&limit=20
- cursor 기반 페이지네이션(권장), 또는 offset/limit



## Data Model
- `property`, `room_type` 테이블 사용(v1)
    - 인덱스:
      - property.city
      - room_type.property_id
    - validation:
      - lat/lng 범위, status enum



## Observability
- Metrics:
      - `catalog_admin_write_total{type=property|room_type}`
      - `catalog_read_latency_seconds`
    - Logs:
      - upsert 시 aggregate_id 기록(property_id/room_type_id)



## Testing
- Integration:
      - Admin create → User read에서 노출 확인
      - status=INACTIVE면 user read에서 404/NOT_FOUND
    - Outbox:
      - create/update 시 outbox row 생성 확인



## Acceptance Criteria
- Admin에서 프로퍼티/룸타입 생성 후 Search/Booking이 참조 가능
    - outbox 이벤트로 Search 인덱싱이 가능할 정도의 payload 포함
