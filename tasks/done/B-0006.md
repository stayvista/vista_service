# B-0006 — Flyway baseline + core schema V1 적용



## Goal
DB 스키마를 애플리케이션 코드와 분리하고, 배포/롤백/검증 가능한 형태로 관리한다.
    v1의 핵심은 **재고/예약 동시성**을 보장하는 테이블/제약조건이다.



## Scope
- `services/db/migrations/V1__core_tables.sql` 적용(테이블/인덱스/제약)
    - Spring 설정:
      - `ddl-auto: validate`
      - `flyway.enabled: true`
    - 로컬에서 마이그레이션 실행/검증 문서화



## Non-goals
- 테넌시/샤딩/멀티리전 스키마는 v2



## Migration policy
- 절대 기존 버전 파일 수정 금지(append-only)
    - 변경은 `V2__...`, `V3__...`로 추가
    - 프로덕션에서는 `baselineOnMigrate` 사용 금지(초기만 예외)



## Smoke test
- docker mysql 기동 후:
      - app 실행 시 flyway가 자동 적용되는지
      - `flyway_schema_history`가 생성되는지
      - 핵심 제약(PK/UK)이 존재하는지(booking/inventory/idempotency/outbox)



## Acceptance Criteria
- 로컬에서 `./gradlew :apps:booking:bootRun` 시 flyway가 성공 적용
    - 스키마 검증 실패 시 앱이 즉시 종료(운영 실수 조기 탐지)
