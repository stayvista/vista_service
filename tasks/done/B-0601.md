# B-0601 — 부하 테스트(k6) 시나리오: 숙소 검색/예약 오픈런



## Goal
오픈런/특가 상황에서 병목(락 대기/DB/캐시/큐)을 재현하고 SLO를 검증한다.



## Scope
- k6 시나리오 3종:
      1) Search steady: 200 RPS, 10분
      2) Hold spike: 0→500 RPS, 2분 버스트
      3) Full funnel: search→detail→hold→confirm (일부 비율)
    - 측정:
      - p95/p99 latency
      - error rate(409,429,5xx)
      - DB lock wait/slow query
      - Redis hit rate
      - Queue 적용 전/후 비교



## Test data prep
- room_type_id 1개를 핫키로 설정
    - 특정 날짜 total=1000으로 설정
    - seed properties 1만건(검색용)



## Thresholds (initial)
- Search p95 < 200ms, p99 < 500ms
    - Hold p95 < 150ms, p99 < 300ms
    - 5xx < 0.1%
    - 409(경쟁패배) 비율은 재고 수준에 따라 허용



## Artifacts
- `services/loadtest/k6/search.js`
    - `services/loadtest/k6/booking_hold.js`
    - `services/loadtest/README.md` (실행 방법, env)



## Acceptance Criteria
- 로컬/스테이징에서 k6를 실행해 리포트를 재현할 수 있다
    - Queue 적용(B-0502) 전/후 비교 수치가 기록된다
