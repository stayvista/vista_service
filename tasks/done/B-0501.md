# B-0501 — Gateway Rate Limiting + Abuse Protection



## Goal
검색/예약은 봇/스크래핑/오픈런 공격에 취약하다.
    Gateway에서 레이트리밋과 기본적인 Abuse 방어를 제공해 백엔드를 보호한다.



## Scope
- Redis 기반 token bucket 또는 sliding window
    - 키:
      - IP 단위(기본)
      - user_id 단위(로그인)
      - endpoint 그룹 단위(search vs booking)
    - 정책 예시(초기):
      - search: 60 req/min/ip, burst 30
      - booking hold: 10 req/min/user, burst 3
      - booking confirm: 5 req/min/user
    - 응답:
      - 429 `RATE_LIMITED` + `Retry-After` 헤더



## Non-goals
- WAF/봇 탐지(캡차) 같은 고급 기능은 v2



## Implementation notes
- gateway filter에서 처리
    - hot key 방지:
      - redis lua script로 원자 처리
      - 키 TTL 최소 2배 윈도우



## Observability
- Metrics:
      - `rate_limited_total{endpoint_group=...}`
      - `rate_limit_redis_errors_total`
    - Logs:
      - ip, user_id, path, limit_key, decision=ALLOW|BLOCK



## Testing
- Unit: lua 결과 파싱, 정책 적용
    - Integration: 100 req burst 시 429 발생 확인



## Acceptance Criteria
- search/booking 경로에 rate limit이 적용된다
    - 429 응답이 표준 에러 포맷을 따른다(B-0005)
