# B-0202 — Ticket Order HOLD API (조건부 UPDATE)



## Goal
사용자가 특정 티켓 이벤트(날짜/시간)에 대해 수량을 HOLD(임시 확보)할 수 있다.
    동시성 상황에서 과판매 0을 보장한다.



## Scope
- `POST /v1/tickets/orders/holds`
    - inventory 차감: `ticket_inventory(event_id)`에 대해 조건부 UPDATE
    - order status=HOLD, expires_at(예: 10분)



## API Contract
### POST /v1/tickets/orders/holds
- `X-Request-Id` (optional): 클라이언트가 생성한 요청 ID (없으면 서버 생성)
- `Idempotency-Key` (쓰기 API 필수): UUID 권장. 동일 요청 재시도 시 동일 결과 반환
- `Authorization` (optional in MVP): `Bearer <token>` (MVP에서는 `X-User-Id`로 대체 가능)
- `X-User-Id` (MVP only): 숫자 사용자 ID (인증 도입 전까지 임시)
Request:
```json
{
  "event_id": 5001,
  "quantity": 2,
  "price": {
    "currency": "KRW",
    "amount_total": 86000
  }
}
```
201 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "order_id": "tord_01J0...",
    "status": "HOLD",
    "expires_at": "2026-02-07T14:05:00Z"
  }
}
```
Errors:
- 409 `TICKET_SOLD_OUT` (reserved+sold+qty > total)



## SQL (atomic reserve)
```sql
UPDATE ticket_inventory
    SET reserved = reserved + :qty
    WHERE event_id = :eventId
      AND (reserved + sold + :qty) <= total;
```



## Transaction
1) event 존재/상태 확인
    2) inventory 조건부 UPDATE (affected_rows=1이어야 성공)
    3) ticket_order(status=HOLD, expires_at) 생성
    4) COMMIT



## Testing
- Concurrency:
      - total=10, 동시에 qty=2로 10개 요청 → 성공 5, 실패 5
    - Idempotency:
      - 같은 key 재시도는 동일 order_id



## Acceptance Criteria
- 과판매 0
    - HOLD 만료 회수(B-0106 패턴 재사용 가능)
