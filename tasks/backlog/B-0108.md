# B-0108 — Search API: 필터/정렬/페이징 + 캐시



## Goal
사용자 검색 UX의 핵심 엔드포인트를 제공한다.
    - 검색은 p99 지연이 낮아야 하며(수백만 유저), 캐시/레이트리밋이 필수다.



## Scope
- `GET /v1/search/properties`
      - q(키워드), city, dates, guests
      - 필터: price range, rating, amenities
      - 정렬: price, rating, distance
      - pagination: cursor(권장) 또는 from/size
    - 캐시:
      - 결과 캐시(짧은 TTL 5~30s) + query normalization
      - 캐시 키에는 사용자별 요소를 넣지 않음(v1은 개인화 없음)



## Non-goals
- 개인화/추천 랭킹은 v2



## API Contract
### GET /v1/search/properties
Query params:
- `q`: 검색어(옵션)
- `city`: 도시(옵션)
- `check_in`, `check_out`: 날짜(옵션, price availability 계산은 v2에서는 더 정교화)
- `adults`, `children`
- `min_price`, `max_price`
- `min_rating`
- `amenities=wifi,parking`
- `sort=price_asc|price_desc|rating_desc|distance_asc`
- `cursor`, `limit`

200 Response:

Errors:
- 400 VALIDATION_ERROR (limit 범위, 날짜 형식 등)
- 429 RATE_LIMITED (봇/스크래핑 방지)



## Caching
- cache layer: Redis
    - key: `search:v1:{hash(normalized_query)}`
    - TTL:
      - default 10s
      - high-traffic 키워드는 30s까지
    - stampede 방지:
      - (권장) singleflight/lock (짧은 mutex 200ms)



## Latency & Protection
- 목표: p95 < 200ms, p99 < 500ms
    - 보호:
      - rate limit: IP/user 단위
      - 요청 파라미터 제한:
        - limit 최대 50
        - from/size 대신 cursor 권장



## Observability
- Metrics:
      - `search_requests_total{cache=hit|miss}`
      - `search_latency_seconds`
      - `search_opensearch_errors_total`
    - Logs: normalized_query_hash, cache_hit, took_ms



## Testing
- Integration(OpenSearch):
      - seed data 인덱싱 후 검색 결과 반환
      - 캐시 hit/miss 동작(2회 호출)



## Acceptance Criteria
- 기본 필터/정렬/페이지네이션 동작
    - 캐시 적용으로 2회 호출 latency 개선 확인
