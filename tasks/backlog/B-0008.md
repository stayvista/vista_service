# B-0008 — Outbox relay(DB→Kafka) 구현



## Context
결제/알림/바우처발급/검색 인덱싱 같은 외부 효과를 트랜잭션 안에서 직접 호출하면:
    - 느려지고
    - 실패 시 롤백/중복 처리 문제가 생기고
    - 운영 중 장애 전파가 커진다.

    해결: **Transactional Outbox**  
    도메인 트랜잭션 내에서 outbox_event 테이블에 이벤트를 기록하고,
    별도 relay가 Kafka로 전달한다(at-least-once).



## Goal
- 도메인 트랜잭션 커밋과 이벤트 기록이 원자적으로 보장된다.
    - relay는 `FOR UPDATE SKIP LOCKED`로 병렬 처리 가능하다.
    - Kafka publish는 at-least-once → consumer는 idempotent하게 처리한다.



## Scope
- `outbox_event` 테이블 사용(v1 스키마)
    - relay 프로세스(스케줄러 or 별도 app 모듈):
      - batch로 미발행 이벤트를 가져와 publish
      - 성공 시 상태 변경(PUBLISHED) + published_at 기록
      - 실패 시 retry_count 증가, backoff, dead-letter 상태 전환
    - 표준 이벤트 envelope:
      - `event_id`(UUID/ULID), `event_type`, `aggregate_type`, `aggregate_id`, `payload`



## Non-goals
- exactly-once end-to-end 보장은 하지 않음(복잡도 대비 효용 낮음)
    - 운영용 DLQ 토픽 정책은 v2(로컬에서는 기본만)



## SQL (fetch pattern)
```sql
-- batch size: 100
    SELECT id, event_id, event_type, payload_json
    FROM outbox_event
    WHERE status = 'NEW'
    ORDER BY id
    LIMIT 100
    FOR UPDATE SKIP LOCKED;
```

```sql
UPDATE outbox_event
    SET status='PUBLISHED', published_at=NOW(3)
    WHERE id IN (...);
```



## Reliability rules
- publish 성공 기준:
      - Kafka producer send ack(acks=all) 성공
    - 실패 처리:
      - retry_count++ (최대 20)
      - `next_attempt_at` 컬럼 있으면 사용(없으면 sleep/backoff)
      - max 초과 시 `status='DEAD'`로 전환 + 알람
    - consumer idempotency:
      - `event_id`를 DB에 기록하거나, 비즈니스 키로 중복 제거



## Observability
- Metrics:
      - `outbox_new_total`, `outbox_published_total`, `outbox_failed_total`
      - `outbox_lag_seconds` = now - created_at (p95/p99)
    - Logs:
      - publish 실패 시 `event_id`, `event_type`, `retry_count`, `exception`
    - Alerts:
      - DEAD 증가 > 0
      - lag p99 > 60s



## Testing
- Integration:
      - 트랜잭션 커밋 후 outbox row가 생성되는지
      - relay 실행 후 Kafka에 메시지가 publish되는지
      - relay 중복 실행(2 인스턴스)에서도 중복 publish가 최소화되는지(SKIP LOCKED)



## Acceptance Criteria
- booking confirm 시 `BookingConfirmed` 이벤트가 outbox → Kafka로 전달된다(샘플)
    - relay 재시작/크래시 후에도 미발행 이벤트가 유실되지 않는다
