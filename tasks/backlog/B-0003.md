# B-0003 — Kotlin/Spring Boot 멀티모듈 기본 골격 생성



## Goal
서비스가 늘어나는 통합 여행 플랫폼에서 “서비스 경계”를 명확히 하고,
    공통 코드/계약/운영 기능을 재사용할 수 있도록 **Gradle Kotlin DSL 멀티모듈** 골격을 만든다.



## Target modules (v1)
```text
services/
    ├─ apps/
    │  ├─ gateway/      # BFF/API Gateway (rate limit, queue gate, auth stub)
    │  ├─ catalog/      # 숙소/룸타입/요금/정책
    │  ├─ booking/      # 숙소 booking hold/confirm/cancel
    │  ├─ search/       # OpenSearch query API (read-heavy)
    │  ├─ ticket/       # 티켓/체험 주문 + 바우처
    │  ├─ geo/          # 주변 POI
    │  └─ chatbot/      # RAG 추천 (MVP)
    └─ libs/
       ├─ common-web/   # error envelope, filters, request-id, validation helpers
       ├─ common-db/    # jpa config, tx helpers, outbox/idempotency repositories
       └─ common-observability/ # logging/metrics/tracing
```



## Scope
- `settings.gradle.kts`에 include 구성
    - 공통 dependency BOM/버전 고정
    - app 모듈은 각각 독립 실행 가능(포트/프로필 분리)
    - 로컬 프로필:
      - `application-local.yml` (mysql/redis/kafka/opensearch)



## Non-goals
- 실제 도메인 기능 구현은 각 도메인 티켓(B-010x 등)에서 수행



## Implementation notes
- Kotlin + Spring:
      - `kotlin("plugin.spring")`, `kotlin("plugin.jpa")` 필수
      - `open-in-view: false`, `ddl-auto: validate`
    - 로깅:
      - Logback JSON encoder(선택) 또는 key=value 구조화
    - API:
      - 각 app은 `/actuator/health` 제공



## Testing strategy baseline
- 모듈별 단위테스트(JUnit5)
    - 통합테스트는 Testcontainers를 공통 fixture로 제공(libs/common-test) (선택)



## Acceptance Criteria
- `./gradlew :apps:booking:bootRun` 같은 방식으로 개별 실행 가능
    - 공통 error contract/filter가 모든 app에 재사용됨
    - 의존성 순환이 없음(app → libs만 의존)
