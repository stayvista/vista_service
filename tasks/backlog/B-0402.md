# B-0402 — Chatbot Service: RAG 기반 여행지 추천 MVP



## Goal
사용자가 원하는 여행 성향/기간/예산/동행/관심사를 입력하면
    추천 일정/장소/상품(숙소/티켓/패키지) 후보를 제안하는 챗봇 MVP를 만든다.



## Scope
- `POST /v1/chat/recommend`
      - 사용자 메시지 + 컨텍스트(지역, 기간, 예산, 동행, 취향)
      - 응답: 추천 카드 리스트 + follow-up 질문
    - RAG(v1):
      - 내부 콘텐츠(도시 소개, POI, 테마 가이드) + 상품 카탈로그를 벡터 검색
      - LLM은 답변 생성, 결과는 “추천 후보”를 구조화하여 반환
    - 안전장치:
      - 비용/시간 제한(토큰 제한)
      - 프롬프트 인젝션 방어(시스템 프롬프트 고정, 도구 출력 검증)



## Non-goals
- 실시간 예약 실행(챗봇이 결제까지)은 v2
    - 개인화(사용자 행동 로그 기반) v2



## API Contract
### POST /v1/chat/recommend
- `X-Request-Id` (optional): 클라이언트가 생성한 요청 ID (없으면 서버 생성)
- `Idempotency-Key` (쓰기 API 필수): UUID 권장. 동일 요청 재시도 시 동일 결과 반환
- `Authorization` (optional in MVP): `Bearer <token>` (MVP에서는 `X-User-Id`로 대체 가능)
- `X-User-Id` (MVP only): 숫자 사용자 ID (인증 도입 전까지 임시)
Request:
```json
{
  "message": "3박4일로 서울 여행. 맛집/전시 좋아하고 예산은 80만원, 커플 여행이야.",
  "context": {
    "city": "Seoul",
    "days": 4,
    "budget_krw": 800000,
    "companions": "COUPLE"
  }
}
```
200 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "answer": "서울에서 전시+맛집 중심으로 4일 코스를 제안할게요...",
    "cards": [
      {
        "type": "POI",
        "title": "국립현대미술관",
        "why": "전시 선호",
        "poi_id": "poi_100"
      },
      {
        "type": "PROPERTY",
        "title": "Wanderly Hotel Seoul",
        "property_id": 1001
      },
      {
        "type": "TICKET",
        "title": "City Museum Pass",
        "product_id": 4001
      }
    ],
    "followups": [
      "숙소는 강남/종로 중 어디가 더 좋아요?",
      "카페 투어도 포함할까요?"
    ]
  }
}
```



## RAG design (v1)
- Retriever:
      - 벡터 인덱스(OpenSearch k-NN 또는 별도 벡터DB)
      - query: 사용자 메시지 + context 요약
    - Documents:
      - city guide(자체 제작), POI 요약, 상품 요약(property/ticket/package)
    - Output validation:
      - 카드 타입/필드가 스키마에 맞는지 서버에서 검증



## Observability
- Metrics:
      - `chat_requests_total`
      - `chat_latency_seconds`
      - `chat_llm_fail_total`
    - Logs:
      - request_id, user_id, model, tokens_in/out(가능하면), latency



## Testing
- Golden tests:
      - 입력 5개에 대해 cards가 비어있지 않음
      - 금칙어/프롬프트 인젝션 시도에 대해 시스템 규칙이 깨지지 않음(최소 방어)



## Acceptance Criteria
- U-0401 챗 UI에서 사용할 수 있는 구조화 응답 제공(cards+followups)
    - 비용/latency 제한 내 동작(p95 < 2s 목표, v1)
