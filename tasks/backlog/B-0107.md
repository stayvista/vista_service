# B-0107 — Search Service: OpenSearch 인덱스/매핑/동기화



## Goal
숙소 검색은 read-heavy이며, 지연/부하가 큰 핵심 구간이다.
    Catalog의 숙소/룸타입 데이터를 OpenSearch에 인덱싱하고,
    변경 사항을 이벤트로 동기화해 **검색을 빠르게** 만든다.



## Scope
- OpenSearch index:
      - `properties_v1` (alias: `properties`)
    - mapping:
      - text: nori 분석기(한글)
      - keyword: city/country/status
      - geo_point: lat/lng
      - numeric: base_price_min, rating, review_count
    - ingestion:
      - 초기 적재(B-0603 seed)
      - 실시간 동기화:
        - outbox 이벤트(PropertyUpserted/RoomTypeUpserted) 소비 → upsert doc
    - reindex 전략:
      - 버전 인덱스 + alias swap



## Non-goals
- LTR/ranking model은 v2
    - 개인화 추천(behavior 기반)은 v2



## Index document shape (example)
```json
{
  "property_id": 1001,
  "name": "Wanderly Hotel Seoul",
  "city": "Seoul",
  "country": "KR",
  "location": {
    "lat": 37.501,
    "lon": 127.0396
  },
  "status": "ACTIVE",
  "room_types": [
    {
      "room_type_id": 2001,
      "name": "Standard Double",
      "max_guests": 2,
      "base_price": 120000
    }
  ],
  "price_min": 120000,
  "rating": 4.4,
  "review_count": 1234,
  "updated_at": "2026-02-07T14:00:00Z"
}
```



## Mapping notes
- `name`/`city`는 nori analyzer
    - `city.keyword`로 필터
    - `location`은 geo_point, 주변 검색/정렬용
    - `price_min`은 정렬/필터용 numeric



## Sync strategy
- source of truth: MySQL(Catalog)
    - Search doc은 “denormalized” 형태(검색 최적화)
    - 이벤트 기반 upsert:
      - consumer는 event_id로 멱등 처리
      - 실패 시 재시도 + DLQ



## Observability
- Metrics:
      - `search_index_upsert_total{result=success|fail}`
      - `search_index_lag_seconds`
    - Logs:
      - property_id, event_id, op=upsert, result



## Testing
- Integration:
      - property create → 이벤트 소비 → OpenSearch doc 존재
      - alias swap 시 검색이 끊기지 않음(health check)



## Acceptance Criteria
- 검색 인덱스가 v1 문서 형태로 생성되고 조회 가능
    - 이벤트 기반 동기화가 작동(샘플 5건)
