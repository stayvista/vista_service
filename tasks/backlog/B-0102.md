# B-0102 — Inventory Admin API: 날짜 범위 재고(total) 설정



## Goal
운영자가 룸타입별 날짜 재고(total)를 캘린더 형태로 설정할 수 있어야 한다.
    Booking HOLD/CONFIRM은 `inventory_night`가 미리 존재한다는 전제를 둔다.



## Scope
- `PUT /v1/admin/room-types/{roomTypeId}/inventory`
      - date range + total 설정(연박 범위 upsert)
    - 규칙:
      - `total`은 **hold+sold 이상**이어야 함 (그보다 낮게 내리면 409)
      - 이미 row가 있으면 total 갱신
      - row가 없으면 생성(hold/sold=0)



## Non-goals
- dynamic pricing(요일/시즌 가격)은 v2



## API Contract
### PUT /v1/admin/room-types/{roomTypeId}/inventory
- `X-Request-Id` (optional): 클라이언트가 생성한 요청 ID (없으면 서버 생성)
- `Idempotency-Key` (쓰기 API 필수): UUID 권장. 동일 요청 재시도 시 동일 결과 반환
- `Authorization` (optional in MVP): `Bearer <token>` (MVP에서는 `X-User-Id`로 대체 가능)
- `X-User-Id` (MVP only): 숫자 사용자 ID (인증 도입 전까지 임시)
Request:
```json
{
  "start_date": "2026-02-10",
  "end_date": "2026-02-20",
  "total": 20
}
```
200 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "room_type_id": 2001,
    "updated_nights": 10
  }
}
```

Error:
- 409 `INVENTORY_TOTAL_BELOW_COMMITTED` (total < hold+sold 인 날짜 존재)



## SQL (Upsert)
```sql
-- 하루 단위로 upsert(배치)
    INSERT INTO inventory_night(room_type_id, stay_date, total, hold, sold)
    VALUES (:roomTypeId, :stayDate, :total, 0, 0)
    ON DUPLICATE KEY UPDATE
      total = VALUES(total),
      updated_at = NOW(3);
```



## Consistency rule (critical)
```sql
-- total을 낮추기 전 검증: 해당 날짜에 total < hold + sold 가 되는지 확인
    SELECT stay_date, total, hold, sold
    FROM inventory_night
    WHERE room_type_id = :roomTypeId
      AND stay_date >= :startDate AND stay_date < :endDate
      AND :newTotal < (hold + sold)
    LIMIT 1;
```
- 존재하면 409 반환하고 전체 변경 거부



## Observability
- Metrics: `inventory_admin_updates_total`, `inventory_total_conflicts_total`
    - Logs: room_type_id, range, total, conflict_date(있으면)



## Testing
- Integration:
      - empty range insert → rows created
      - existing row update → total 변경
      - sold>0 상태에서 total을 sold 미만으로 내리면 409



## Acceptance Criteria
- Booking HOLD가 inventory row 없는 날짜에서는 동작하지 않음(운영 실수 빠르게 드러남)
    - Admin UI(A-0103)가 호출 가능한 단일 API 제공
