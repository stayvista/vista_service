# B-0203 — Ticket Order CONFIRM + 바우처(QR) 발급 이벤트



## Goal
티켓 주문을 확정하고 바우처(입장권)를 발급한다.
    바우처 발급은 outbox 이벤트로 분리하여 중복 발급을 방지한다.



## Scope
- `POST /v1/tickets/orders/{orderId}/confirm`
      - reserved → sold 전환
      - order.status=CONFIRMED
    - outbox 이벤트:
      - `TicketOrderConfirmed`
      - `VoucherIssueRequested`
    - voucher 서비스/핸들러(동일 모듈 내 worker 가능):
      - 이벤트 소비 → voucher 생성(QR payload) → 저장 → `VoucherIssued`
    - Admin 검표 API는 A-0202에서 사용



## API Contract
### POST /v1/tickets/orders/{orderId}/confirm
- `X-Request-Id` (optional): 클라이언트가 생성한 요청 ID (없으면 서버 생성)
- `Idempotency-Key` (쓰기 API 필수): UUID 권장. 동일 요청 재시도 시 동일 결과 반환
- `Authorization` (optional in MVP): `Bearer <token>` (MVP에서는 `X-User-Id`로 대체 가능)
- `X-User-Id` (MVP only): 숫자 사용자 ID (인증 도입 전까지 임시)
Request:
```json
{
  "payment_method": "CARD",
  "payment_token": "paytok_test_abc"
}
```
200 Response:
```json
{
  "request_id": "01J0...",
  "data": {
    "order_id": "tord_01J0...",
    "status": "CONFIRMED",
    "voucher_ids": [
      "vch_01J0...",
      "vch_01J0..."
    ]
  }
}
```
Errors:
- 409 `ORDER_EXPIRED` (HOLD 만료)
- 409 `ORDER_STATE_CONFLICT`



## SQL (reserve→sold)
```sql
-- inventory 전환
    UPDATE ticket_inventory
    SET reserved = reserved - :qty,
        sold = sold + :qty
    WHERE event_id=:eventId AND reserved >= :qty;
```



## Voucher model (suggestion)
- voucher(id, order_id, user_id, event_id, status, qr_payload, issued_at, redeemed_at, ...)
    - qr_payload는 서명된 토큰(JWT/PASETO) 권장:
      - claims: voucher_id, order_id, event_id, exp



## Idempotency & duplication control
- confirm API는 Idempotency-Key 필수
    - voucher 발급 consumer는 `event_id`(outbox event_id)로 중복 처리 방지
    - voucher 테이블에 `UNIQUE(order_id, sequence)` 같은 제약 권장



## Testing
- confirm 성공 → sold 증가, reserved 감소
    - voucher 발급 이벤트 중복 소비 → voucher 수량이 중복 생성되지 않음
    - Admin redeem(검표) 시 1회만 성공(UNIQUE/상태전이)



## Acceptance Criteria
- confirm 후 voucher가 생성되고, 사용자에게 조회 가능(또는 async 완료 알림)
    - 중복 confirm/중복 이벤트에도 voucher 수량이 정확히 qty만 생성
