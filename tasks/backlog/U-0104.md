# U-0104 — 예약 플로우 UI(HOLD→CONFIRM, 카운트다운/대기열 대응)



## Goal
사용자가 룸타입 선택 후:
    1) HOLD 생성(재고 확보)
    2) 남은 시간(카운트다운) 안에 결제/확정(CONFIRM)
    을 완료할 수 있는 예약 플로우를 만든다.



## Scope
- routes:
      - `/checkout/booking` (HOLD 생성 + 결제)
      - `/booking/complete` (완료 페이지)
    - UI states:
      - HOLD creating → countdown start
      - HOLD success → 결제 입력
      - CONFIRM success → complete
      - 409 OVERBOOKED → “다른 날짜/룸타입” 안내
      - 429 QUEUE_REQUIRED → 대기열 화면으로 이동



## API integration
### 1) HOLD
- POST `/v1/bookings/holds`
- headers: `Idempotency-Key` 필수(클라에서 UUID 생성)
- 성공 시 `expires_at` 받아 countdown

### 2) CONFIRM
- POST `/v1/bookings/{bookingId}/confirm`
- idem key 별도로 생성(버튼 더블클릭 방지)

### (선택) Queue
- 429 `QUEUE_REQUIRED` 시:
  - POST `/v1/queue/join` → ticket 획득
  - GET `/v1/queue/status` 폴링 → admit_token 받으면 재시도



## Countdown behavior
- expires_at 기준으로 남은 시간을 계산
    - 60초 이하: 경고 배너
    - 만료 시:
      - 결제 버튼 비활성
      - “다시 시도”로 HOLD 재생성 유도



## Payment UI (v1 stub)
- 실제 카드 입력 대신:
      - “테스트 결제” 버튼 + payment_token 자동 생성
    - v2에서 실제 PG 연동으로 교체 가능하도록 컴포넌트 분리



## Acceptance Criteria
- HOLD→CONFIRM 성공 시 완료 페이지로 이동한다
    - 오픈런 상황에서 overbook/queue 에러를 UX로 처리한다
